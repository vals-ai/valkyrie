---
title: "Publish a dataset"
description: "Publish task folders as a versioned dataset in your benchmark, tag versions, and run agents on them."
---

A dataset holds tasks your organization publishes to Valkyrie, with no benchmark service to run.
Each push makes an immutable version.

## Lay out the task folders

- Put each task in its own folder, named by its task ID, under one parent folder.
- A task folder holds `task.toml`, `instruction.md`, and `tests/test.sh`. It can also hold
  `environment/` and `solution/`.
- A `metric.py` in the parent folder computes the dataset's score from the task rewards.
- A `dataset.toml` in the parent folder pins the exact tasks and their digests, and its version
  becomes a tag.

## Start a task from a sandbox snapshot

Set `snapshot` in `[environment]` instead of an image or a Dockerfile. `snapshot_target` optionally picks the Daytona target that holds it.

```toml
[environment]
snapshot = "my-snapshot"
snapshot_target = "us"
```

- A Daytona snapshot sets the sandbox's CPU, memory, and disk. Local Docker can't run snapshots.

## Read secrets in task environments

- In `task.toml`, use a whole-value `${NAME}` to read a secret available to the run.
  For JSON secrets, this reads the field named `NAME`.
- Use `${SECRET#FIELD}` to select a different JSON field, or
  `${SECRET#FIELD:-fallback}` to use a default when the secret or field is unavailable.
- These references work in agent, verifier, verifier sandbox, and solution environment
  values, including step verifiers. A field reference requires a JSON object secret.

```toml
[verifier.env]
API_KEY = "${ClientConfig#API_KEY}"
```

## Call models from a verifier

- List the Model Gateway models that the verifier calls in `[verifier].models`. A step can
  list its own in `[steps.verifier].models`.
- When the run has a project with a Gateway key, the verifier gets `MODEL_GATEWAY_URL` and a
  grading token as `MODEL_GATEWAY_API_KEY`. The token can only query the listed models, and it
  ends when grading ends.
- Only the sandbox that runs the verifier can reach the Gateway host, and only while it grades.
  A separate verifier starts with no network and gets the Gateway host before the verifier
  runs.
- A task that lists models fails to grade when the run has no grading token.
- A compose verifier can't list models while its environment has `network_mode = "no-network"`.
- To move a verifier from a Gateway secret to `models`, remove `MODEL_GATEWAY_URL` and
  `MODEL_GATEWAY_API_KEY` from `[verifier].env`. A task that lists models and also sets either
  name is not valid.

```toml
[verifier]
network_mode = "no-network"
models = ["openai/gpt-4o"]
```

## Push a folder

```bash
valkyrie dataset push my-benchmark/my-dataset ./tasks --tag v1
```

- The benchmark and the dataset are created when they don't exist yet.
- Only tasks the dataset doesn't store yet are uploaded. Pushing an unchanged folder makes no
  new version.
- Every version gets the `latest` tag, plus each `--tag`.

## Install from Harbor, GitHub, or Hugging Face

```bash
valkyrie dataset install tb/tb2 terminal-bench/terminal-bench-2 --location harbor
```

`--location github` and `--location hugging_face` take a repository as `owner/name` or its URL.

<Note>
  `--location harbor` needs `uv` or the `harbor` CLI on your `PATH`.
</Note>

## Tag versions

```bash
valkyrie dataset versions my-benchmark/my-dataset

valkyrie dataset tag my-benchmark/my-dataset@2 stable

valkyrie dataset untag my-benchmark/my-dataset v1
```

- `latest` always moves. Another tag on a different version moves only with `--force`.
- `untag` removes a tag. `latest` can't be removed.

## Run an agent on a dataset

```bash
valkyrie run start --agent my-agent --dataset my-benchmark/my-dataset@stable
```

- After `@`, pass a revision number, a tag, or a digest. Without it, the run uses `latest`.
- `--task-range`, `--task-ids`, and `--concurrency` work as in [Start a run](/runs/start).

## Inspect tasks

```bash
valkyrie dataset task list my-benchmark/my-dataset@2

valkyrie dataset task download my-benchmark/my-dataset@2 hello
```

The download is saved as `TASK_ID.zip` unless you pass `--output`.
