Sign in to use the CLI and Python SDK on your machine. For continuous integration (CI),
create an access key instead.

## Sign in

```bash
valkyrie login
```

Your browser opens to sign in with your Google account. On a machine without a browser,
add `--no-browser` and open the printed link yourself.

- You stay signed in between commands.
- When your session expires, the CLI asks you to sign in again.

```bash
# Check your account and organization
valkyrie whoami

# Sign out
valkyrie logout
```

## Create an organization

Runs, agents, secrets, and access keys belong to an organization, and its members see its
runs.

After signing in, create your organization:

```bash
valkyrie org create my-team
```

- Choose an unused ID of 3–63 lowercase letters, digits, dots, or hyphens. Start and end
  with a letter or digit.
- You become its admin, and later commands use this organization.

## Join an organization

1. Ask one of its admins to run `valkyrie org invite you@example.com` with your email
   address.
2. Sign in with `valkyrie login` by using that address.
3. List your invitations with `valkyrie org list`.
4. Accept one with `valkyrie org accept acme`.

Invitations expire after 14 days. Decline one with `valkyrie org decline acme`.

## Switch organizations

The CLI uses one organization at a time. To choose another:

```bash
# List your organizations
valkyrie org list

# Switch to one
valkyrie org use acme
```

## Manage members

If you're an admin, you can invite teammates, see members, and remove people:

```bash
valkyrie org invite teammate@example.com

# List members and pending invitations
valkyrie org members

# Remove a member, or cancel an invitation
valkyrie org remove teammate@example.com
```

- Removing a member also deletes the access keys they created for the organization.
- Sign in to manage membership. An access key cannot do this.

## Create an access key for CI

Use an access key to run Valkyrie from CI or a machine where you can't sign in. Create the
key while signed in on your own machine:

```bash
valkyrie token create github-actions --expires-in-days 30
```

- Copy the key when it appears. You cannot display it again.
- Set the key as `VALKYRIE_API_KEY` where the job runs.
- Keys expire after 30 days by default. You can choose between 1 and 90 days.

There is no command to list keys, so keep the key ID. Revoke a key with:

```bash
valkyrie token revoke KEY_ID
```

Replace *`KEY_ID`* with the key ID that `valkyrie token create` printed.

- A revoked key can keep working for up to a minute.
- Sessions already created with that key remain valid until they expire.
- Creating and revoking keys requires you to sign in.

CI runs use your
[default provider](/get-started/sandbox-providers#choose-the-provider-for-a-run) and
[saved benchmark services](/benchmarks/custom-services). To keep CI runs independent of
those settings, pass `--provider` and `--ignore-custom-services` when starting a run.

## Choose a Tracker

Valkyrie connects to Vals AI's hosted service by default. You only need to change this if
you [run your own Tracker](/self-hosting/local-tracker) or have been given another server
address:

```bash
VALKYRIE_URL=https://tracker.example.com valkyrie login
```

- Signing in saves that address for later commands.
- Use `VALKYRIE_URL` to choose a different Tracker for one command.
- Signing out returns the CLI to the hosted service.

An access key works only on the Tracker that issued it. Set `VALKYRIE_URL` beside `VALKYRIE_API_KEY`
when the key comes from another Tracker.

## Configure the Python SDK

`ValkyrieClient()` uses the same Tracker and login as the CLI. To choose them in code, pass
a `ValkyrieConfig`:

```python
from valkyrie.sdk import ValkyrieClient, ValkyrieConfig

config = ValkyrieConfig(url="https://tracker.example.com", api_key="ACCESS_KEY")
async with ValkyrieClient(config) as client:
    page = await client.runs.list()
```

Replace *`ACCESS_KEY`* with an access key, or leave out `api_key` to use your login.

See the [`ValkyrieConfig` reference](/reference/sdk/models/config#valkyrie-config) for all
connection options.

## Environment variables

| Variable | Effect |
| --- | --- |
| `VALKYRIE_API_KEY` | Authenticates every request with this access key instead of a saved login. |
| `VALKYRIE_URL` | Sends requests to this Tracker instead of your last login's Tracker or the hosted one. |
| `VALKYRIE_CLI_LOGS` | Show extra CLI logs when set to `true`. |
