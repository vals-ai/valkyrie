Follow a run while it goes, find out why tasks failed, and look up earlier runs.

- Every command is in the [`valkyrie run` reference](/reference/cli/run).
- To do the same from Python, see [Manage runs with Python](/sdk/runs).

In the commands on this page, replace *`RUN_ID`* with the run's ID, which
`valkyrie run start` prints, and *`TASK_ID`* with a task's
ID.

## Follow a run

```bash
valkyrie run fetch RUN_ID --connect
```

This prints the run's details, then its progress until the run finishes.

- Press **Control+C** to stop watching. The run keeps going.
- Without `--connect`, `run fetch` prints one snapshot. `--format json` prints the SDK's
  `RunSnapshot`: the run and its launch metadata.
- CLI snapshots omit saved agent configuration and agent secret references. Use the SDK to read
  the full launch metadata when you need it.

A run ends as `FINISHED`, `ERROR`, or `STOPPED`. The command exits with 0 whichever way the
run ends, so check the status rather than the exit code.

### Follow a run from a script

```bash
valkyrie run fetch RUN_ID --connect --format jsonl
```

Each line is an SDK model as JSON.

- The first line is the `RunSnapshot`. Each line after it is a `RunStreamEvent` with an `event` field.
- `update` lines carry the run. The last line is `complete`, `error`, or `disconnect`.
- After `complete`, check `run.details.status` in the last `update` for how the run ended.
- If the stream ends without a final event, the command exits with 1.

## Check several runs at once

```bash
valkyrie run status --ids RUN_ID_1,RUN_ID_2 --format json
```

Replace *`RUN_ID_1`* and *`RUN_ID_2`* with the runs' IDs.


The output keeps the order you gave. IDs that don't exist or that you can't see are left out,
and the command then exits with 1.

## Find failed tasks

```bash
valkyrie run errors RUN_ID
```

This shows the run's own errors and each failed task's error. To look closer:

```bash
# Tasks that failed, one page at a time; add --offset for later pages
valkyrie run tasks RUN_ID --status ERROR

# One task's status, grade, error and time breakdown
valkyrie run task RUN_ID TASK_ID

# Temporary links to one task's files and logs
valkyrie run task-artifacts RUN_ID TASK_ID
```

For scripts, add `--format json` to any of these.

## Check how long a task took

```bash
valkyrie run task RUN_ID TASK_ID
```

The output includes the task's exit reason and its time breakdown:

| Field | Meaning |
| --- | --- |
| `agent_caused_exit_reason` | `TIMEOUT` when the generation limit stopped the agent, or `OS_KILLED` when the operating system stopped it |
| `base_generation_allowance_seconds` | The task's generation limit, or `null` for none |
| `generation_elapsed_seconds` | Generation time counted against the limit |
| `sandbox_build_duration` | Seconds spent creating the sandbox |
| `agent_run_duration` | Seconds the agent's command ran, timed from its own start, so it can differ from `generation_elapsed_seconds` |
| `evaluation_run_duration` | Seconds spent grading |

See [Task time limits](/runs/time-limits) for what counts toward each limit.

## Read logs

```bash
valkyrie run logs RUN_ID
```

Narrow the logs to one task, to text, or to a time range. Times need a time zone, and logs
at exactly those times are included:

```bash
valkyrie run logs RUN_ID --task-id TASK_ID --query "rate limit" \
  --since 2026-01-01T00:00:00Z --until 2026-01-01T01:00:00Z
```

To watch new log lines arrive, add `--follow` with `--task-id`. For scripts, add
`--format jsonl`.

## Search your run history

```bash
valkyrie run list --benchmark-name swebench --status IN_PROGRESS
```

Filter by `--agent-name`, `--benchmark-name`, `--model`, `--dataset`, `-l` for the label,
`--status`, and `--started-by`, and sort with `--order-by asc` or `desc`. Page through the
list with **h** and **l**, and quit with **q**. To print every match as one JSON document:

```bash
valkyrie run list --format json --all --status IN_PROGRESS
```

JSON output is the SDK model the command reads, here `FetchBenchmarksResponse`. Scores that
aren't finite numbers are `null`.

`valkyrie run filter-options` lists the agents, benchmarks, models, and other values your
organization's earlier runs used, which are the values the filters accept.

## Inspect the priority queue

On a Tracker that queues tasks in shared sandbox pools, see your organization's waiting and
active tasks:

```bash
valkyrie queue status
```

- Waiting tasks are ordered by priority, then by when they joined the queue.
- Positions count every task in the pool, including other organizations' tasks, which aren't
  listed.
- The command only reads the queue.

Each list shows up to 100 entries. When there are more, the output prints the offset of the
next page. Pass `--waiting-offset` and `--active-offset` to page through each list
separately:

```bash
valkyrie queue status --waiting-offset 100 --active-offset 100
```

The queue changes between calls, so a task can appear on two pages or on none.

## Browse runs in the terminal

```bash
valkyrie tui
```

`valkyrie tui` lists your organization's recent runs with live status, so your
teammates' runs show up too. It only reads, so stop or retry a run with `valkyrie run`.

To try it on sample data, add `--fake`.

| Key | Action |
| --- | --- |
| **Enter** | Open the selected run or task |
| **e** | Group the run's errors by category and message |
| **/** | Filter the list, or search a task's log |
| **n**, **N** | Go to the next or previous search match |
| **y** | Copy the `valkyrie` command for the selection |
| **s** | Show runs from the last 2, 7, or 30 days |
| **d** | Browse your organization's datasets and their tasks |
| **c** | Switch to another Tracker you've signed in to |
| **Esc** | Go back |
| **?** | List every key |
