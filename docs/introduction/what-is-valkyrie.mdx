Valkyrie runs your AI agent on benchmark tasks, such as coding problems from SWE-bench
Verified or Terminal-Bench 2.0.

- Choose an agent and a dataset of tasks, then start a run from the CLI or Python SDK.
- Tasks run in parallel, each in its own sandbox: a separate cloud environment.
- Your team can view each run's score, logs, outputs, and settings.

## Why agents need different evaluation infrastructure

An agent needs more than a question and an answer to work on a task:

- Each task needs its own sandbox with the right repository and tools.
- The agent works in it for minutes or hours.
- The benchmark grades the work when the agent finishes.

Valkyrie prepares these environments, runs tasks in parallel, and saves the results so
your team can compare runs without setting up each task by hand.

## How Valkyrie divides the work

- **Benchmark authors** [publish datasets](/benchmarks/datasets) with tasks and grading
  instructions.
- **Agent authors** [package an agent](/agents/package-an-agent) with instructions for
  installing and running it.
- **People running evaluations** choose an agent and dataset. Valkyrie handles task setup,
  execution, and grading.

## A run, step by step

1. Choose an agent, dataset, and sandbox provider, then start a run.
2. Valkyrie creates a sandbox for each task and prepares the agent and task.
3. The agent works until it finishes or reaches its [time limit](/runs/time-limits).
4. Valkyrie saves the outputs, grades the work, and deletes the sandbox.
5. Read the run's score and task results. Use the logs to investigate failures.

You can [follow progress and logs](/runs/monitor) while the run is in progress.

## What a run guarantees

- **Saved versions and settings.** Each run on a published dataset records its version,
  agent, and settings so you can compare results.
- **Agent updates don't change existing runs.** To use new agent files in a retry,
  [retry with `--update-agent`](/runs/manage#resume-or-retry).
- **Enforced limits.** Valkyrie stops the agent when its time runs out and applies the
  task's network restrictions.
- **Shared results.** Your organization can read the logs, outputs, and results from any
  member's run.
- **Runs survive routine upgrades.** Running tasks finish on their original version.
  - Maintenance can stop tasks, but you can resume the run afterwards.

## How far it scales

- Use `--concurrency` to choose how many tasks run at once.
- Your sandbox provider's quota and model provider's rate limits also limit parallel work.

## Core concepts

- **Run:** one agent evaluated on one benchmark dataset. A run is made of tasks.
- **Task:** one problem from the dataset, run in its own sandbox.
- **Sandbox provider:** the service that creates sandboxes, such as Daytona or Modal. Runs
  use your organization's own provider account.
- **Organization:** the owner of runs, agents, and secrets. Members of an organization see
  its runs.

## Where Valkyrie runs

- **Hosted by Vals AI.** Sign in and create an organization to use the hosted service,
  where Vals AI stores your results.
  - Sandboxes run on your own provider account.
- **On your machine.** Run the Tracker yourself with no AWS account, as in
  [Run Tracker locally](/self-hosting/local-tracker).

## Paper

Valkyrie is described in [Valkyrie: A Microservice-Based Framework for Scalable Evaluation
of AI Agents](https://doi.org/10.1145/3786335.3813231) (CAIS '26). A reading copy is on
[alphaXiv](https://www.alphaxiv.org/abs/valkyrie).

The paper ran four agents on SWE-bench Verified and Terminal-Bench 2.0 through Valkyrie,
with the same sandbox settings for every run and no per-run setup. Their accuracy is
consistent with the scores on each benchmark's public leaderboard:

| Agent | SWE-bench Verified | Terminal-Bench 2.0 |
| --- | --- | --- |
| SWE-agent (Claude Sonnet 4.6) | 77.6% | 56.17% |
| mini-SWE-agent (Claude Sonnet 4.6) | 76.2% | 61.79% |
| Claude Code (Claude Sonnet 4.6) | 51.4% | 57.3% |
| Codex CLI (GPT-5.3-Codex) | 66.0% | 66.29% |
